# 中文源码导读

这是《最后核心》的源码导航。脚本中的中文注释解释现有离线实现。

## 建议阅读顺序

1. `scripts/main.gd`：先看 `_ready()` 和 `show_menu()`，理解游戏怎样进入主菜单；再看 `begin_run()`、`start_wave()`、`on_wave_end()`，串起一局游戏。
2. `scripts/simulation.gd`：先看 `new_run()` 的状态字典，再看 `place()`、`rebuild_paths()` 和 `step()`，理解建造、寻路和战斗。
3. `scripts/board.gd`：看 `point()`、`cell_at()` 和 `_gui_input()`，理解鼠标像素位置如何对应棋盘地格；`_draw()` 负责动态画面。
4. `scripts/storage.gd`：看 `save()` 和 `settle()`，理解保存、备份和避免重复领取金币。
5. `tests/`：通过输入和断言理解规则边界。测试里的强化配置有时是专门的测试条件，不代表新玩家的初始数值。

## 从点击到战斗

玩家点击棋盘 → `board.gd` 发出 `cell_clicked` 信号 → `main.gd` 的 `on_cell_clicked()` 接收 → `simulation.gd` 检查建造是否合法 → 界面读取最新状态重新绘制。

开波后，`main.gd` 用帧时间累积器反复调用 `sim.step()`。每次模拟推进固定的 1/30 秒，游戏倍速改变调用次数。炮台攻击、敌人移动和波次结束都由模拟器判断，绘图代码不负责决定伤害。

## 常用字段

| 字段 | 含义 |
|---|---|
| `sim.s` | 当前出征的状态字典 |
| `s.state` | 准备、编辑、战斗、休整、领奖、商店或结束阶段 |
| `s.wave` / `s.completed` | 当前波数 / 已完成波数 |
| `s.budget` | 建造预算，拆除可返还 |
| `s.income` / `s.spent` | 本局累计金币收入 / 商店消费 |
| `s.meta` | 开始出征时复制的永久培养数据 |
| `s.growth` | 本次出征获得的属性强化 |
| `s.buildings` | 按地格字符串键索引的建筑数据 |
| `enemies` / `shots` | 当前敌人 / 短暂的攻击显示数据 |
| `fields` / `paths` | 距离场 / 用于预览的路线 |
| `checkpoint` | 开始当前波之前的状态快照 |
| `store.data` | 局外金币、研究、设置、纪录及保存的出征 |

普通怪与特殊怪各有一份距离场。距离场从核心向外做广度优先搜索，敌人每次走向距离值更小的相邻格。地形的减速或伤害不改变最短路选择。

战斗期间退出时保存的是波前检查点，并非当前敌人位置。重新打开后从这一波开始前恢复，已经完成的波次仍然保留。

## 阅读时会遇到的 GDScript 写法

- `extends`：指定脚本继承的类型。界面使用 `Control`，模拟器使用 `RefCounted`。
- `var` / `const`：声明变量 / 常量；冒号后面可标注类型。
- `func`：定义函数；缩进确定函数和分支的范围。
- `return`：返回结果并结束当前函数；提前返回常用于拒绝非法操作。
- `signal`、`.connect()`、`.emit()`：声明、连接和发出信号，把输入与处理逻辑分开。
- `func(): ...`：匿名函数，常用于按钮点击回调。
- `preload()`：预加载脚本资源；`.new()` 创建实例。
- `duplicate(true)`：深拷贝嵌套数据，让快照不随原字典一起改变。
- `res://`：项目资源目录；`user://`：游戏用户数据目录。
- `#`：注释，不执行。JSON 配置不支持这种注释，因此 `data/rules.json` 保持标准 JSON。

## 修改入口

地图、炮台、敌人和地形基础数值在 `data/rules.json`；实际成长公式在 `simulation.gd`。界面按钮和页面布局在 `main.gd`，配色与建筑图形主要在 `board.gd`。

手机版部署先由 main.gd 保存 draft，独立模拟器验证后，确认时才写入真实防线。board.gd 负责射程、拖动痕迹及动态路线。

修改规则后先运行 README 中的核心测试。只修改注释无需重新打包游戏程序；学习源码时用 Godot 导入项目根目录的 `project.godot` 即可。
